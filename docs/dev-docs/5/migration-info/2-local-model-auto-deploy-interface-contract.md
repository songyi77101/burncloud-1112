## 迁移差异

1. **任务请求与手动路径请求分离**：新接口只提交模型、来源、修订、GGUF 文件标识、摘要及后端；不接受旧手动部署的 model_path，也不接受客户端指定任意 artifact_uri。权威目录核对和真实摘要验证仍由服务端负责。
2. **由长时间同步等待改为任务查询**：新 POST 返回 202、稳定任务 ID 和 Location；GET 同时读取模型与运行时子任务；DELETE 先登记取消意图，在清理真正完成后才报告 cancelled。既有手动部署和停止接口不改为这些语义。
3. **明确任务与当前可对话状态的差别**：succeeded 保留历史部署结果；ready_to_chat 额外核对当前同代次进程和路由。服务重启、停止、路由繁忙或代次替换不能使历史成功快照冒充当前可用服务。
4. **细化重复提交与取消边界**：同一身份和请求后端在途任务原子复用；取消未完成前仍占用该键；取消和成功提交串行判定，终态不能被迟到结果覆盖。共享准备不因其中一个父任务取消而被全局停止。
5. **补充后端选择前的预算展示**：既有 resolve 请求增加可选 backend，候选增加 deployment_estimate；旧字段仍保留。未传 backend 按已确认的 auto 语义处理，因此候选集合可能与旧的 GPU 显存筛选不同；不能通过清空原始资源要求实现兼容。CUDA 下载量、磁盘预算和驱动要求须在主动提交前展示。
6. **区分请求错误和已登记任务失败**：非法请求在 HTTP 层拒绝；后台阶段失败写入任务 error，GET 仍返回查询成功。清理错误另行保留，不覆盖原始错误，也不伪造取消成功。
